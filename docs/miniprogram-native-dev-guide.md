# 周杰伦粉丝答题 - 微信小程序原生开发技术要点文档

> 💡 本文档为纯微信小程序原生开发（WXML + WXSS + JS，无第三方框架）的完整技术指引，所有业务规则与现有 Web 版完全对齐，可直接对照开发。

---

## 📁 一、整体架构

### 1.1 技术栈
- **视图层**：WXML + WXSS
- **逻辑层**：原生 JavaScript（不用 TS，不用任何框架）
- **后端接口**：直接复用现有 Nitro 接口（只需新增微信登录接口）
- **管理后台**：Web 版保留不变，小程序不做任何管理功能

### 1.2 页面结构（共 6 个页面）
```
pages/
├── index/        # 首页（等级徽章 + 模式入口）
├── login/        # 登录页（微信一键登录）
├── quiz/         # 休闲模式答题页
├── adventure/    # 冒险模式答题页
├── ranking/      # 周榜排行榜
└── record/       # 我的战绩页
```

### 1.3 全局配置要点
- 导航栏颜色：`#8b1e2b`（和 Web 版一致）
- 标题：「周杰伦粉丝答题」
- 底部 TabBar：3 个（首页 / 排行榜 / 我的）
- 关闭小程序自带下拉刷新，需要自己做的话单独加

## 💾 二、本地存储层（必须严格对齐）

所有存储项用 `wx.setStorageSync()` / `wx.getStorageSync()`，key 和格式完全如下：

| Key | 存储格式 | 说明 |
|-----|---------|------|
| `token` | `string` | 登录凭证，空表示未登录 |
| `localBestScore` | `{ score: number, costMs: number, week: string }` | 本周最高分，`week` 格式 `2024-W01`，用于周清零判断 |
| `quizSession` | `{ questions: Array, currentIndex: number, category?: string }` | 休闲模式断点续答进度 |
| `adventureDailyCount` | `{ date: string, count: number }` | 冒险模式每日挑战次数，`date` 格式 `2024-01-01` |
| `myRecords` | `Array<{ totalScore: number, totalCostMs: number, records: Array }>` | 历史答题战绩列表 |

## 🔌 三、后端 API 对接

### 3.1 可直接复用的接口（90%）
直接调用现有 Web 版接口，域名在 `app.js` 里统一配置：
```
GET  /api/questions/random?count=10&category=xxx   # 随机题
GET  /api/questions/sync                            # 全量题库同步
GET  /api/rankings/list                             # 排行榜列表
POST /api/rankings/submit                           # 提交成绩
GET  /api/auth/me                                   # 获取当前用户信息
```

### 3.2 需要后端新增的接口
```
POST /api/auth/wechat
Body: { code: string }   # wx.login() 获取的临时 code
Return: { token: string, user: { id, nickname, avatar } }
```

### 3.3 请求封装要点
- 统一在 `app.js` 里封装 `request()` 方法
- 请求头自动带 `Authorization: Bearer ${token}`
- 401 状态码自动清除 token，跳转到登录页
- 所有请求默认加 `wx.showLoading()`，完成后自动隐藏
- 超时时间设为 10 秒

## 🧮 四、核心业务逻辑规则（必须严格对齐）

### 4.1 粉丝等级计算规则
**触发时机**：首页加载、答题完成后重新计算
**计算范围**：最近 50 道休闲模式答题记录（冒险模式不算）
**加权权重**：
| 题型 | 权重 |
|------|------|
| 填空题 | 40% |
| 单选题 | 35% |
| 判断题 | 25% |

**等级划分**：
| 加权正确率 | 等级 |
|-----------|------|
| 0-40% | 路人粉 |
| 41-70% | 普通粉 |
| 71-90% | 资深粉 |
| 91-100% | 骨灰铁粉 |

**显示逻辑**：
- 未登录 → 显示「🔒 登录解锁等级」
- 已登录但答题 < 50 道 → 显示「🔒 等级待解锁，再答 X 题揭晓」
- 已登录且答题 ≥ 50 道 → 显示 🎖️ 具体等级 + 正确率

---

### 4.2 休闲模式规则
1. 不限次数，随时可以开始
2. 支持断点续答：退出后再进来自动恢复上次的进度
3. 答题完成后，成绩高于本周本地最高分则自动更新
4. 已登录用户自动提交到排行榜，未登录用户仅保存在本地
5. 支持分类选题（混合 / 歌词 / 创作 / 个人经历）

---

### 4.3 冒险模式规则
1. **每日限制 3 次**，次数存在本地，每天 0 点自动重置
2. 每次 100 道混合题，限时 10 分钟（全局倒计时，切后台时间仍在走）
3. 时间到自动交卷，未答的题全部算答错
4. 答题完成后才消耗 1 次次数，中途退出不算
5. 成绩自动保存到本地，已登录用户自动提交到排行榜
6. 进入时先弹窗显示当前等级 + 今日剩余次数，次数用完按钮禁用

---

### 4.4 周榜规则
1. 每周一 00:00 自动清零，使用「周一为一周第一天」的周数计算
2. 排序规则：先按分数降序，同分数按用时升序
3. 游客也能看排行榜，但提交成绩需要登录
4. 本地最高分和服务器周榜周期保持一致，跨周自动清零

---

### 4.5 拼图模式规则
1. 题目带 `puzzleEnabled = true` 且有 `puzzleImage` 字段时触发
2. 拼图完成前，题目和选项都是模糊的，不能点击答题
3. 拼图交互：点击交换模式（推荐，小程序拖拽坑多），或者简单拖拽交换
4. 拼图完成后自动解锁题目和选项
5. 每道题的拼图状态独立，切换题目重置

## 📱 五、每个页面的开发要点

### 5.1 首页 (index)
- ✅ 顶部等级徽章，点击未登录跳转登录，答题不足50道弹出模式选择
- ✅ 4 个入口：休闲模式、冒险模式、排行榜、我的战绩
- ✅ 规则说明弹窗
- ✅ 每次进入页面重新计算粉丝等级

### 5.2 登录页 (login)
- ✅ 只有一个「微信一键登录」按钮，不要账号密码输入
- ✅ 调用 `wx.login()` 获取 code，传给后端换 token
- ✅ 登录成功后自动返回上一页
- ✅ 不要强制用户授权头像昵称，能拿到 openid 就行

### 5.3 休闲模式答题页 (quiz)
- ✅ 顶部进度条 + 题数显示
- ✅ 拼图组件（有拼图题时显示）
- ✅ 单选/判断/填空三种题型适配
- ✅ 答题后显示对错 + 解析
- ✅ 本地自动保存答题进度，下次进入自动恢复
- ✅ 结算页显示得分、用时、是否更新本周最高分

### 5.4 冒险模式答题页 (adventure)
- ✅ 进入时先弹确认框：显示当前等级 + 今日剩余次数
- ✅ 顶部全局 10 分钟倒计时（红色醒目显示）
- ✅ 100 道题，答完或者时间到自动结算
- ✅ 结算后自动增加次数计数，自动提交成绩
- ✅ 中途退出不保存进度，不消耗次数

### 5.5 排行榜页 (ranking)
- ✅ 显示本周 Top 100
- ✅ 显示当前用户的排名（在榜内高亮显示）
- ✅ 未登录用户显示「登录后可参与排名」
- ✅ 每周一自动清零提示

### 5.6 我的战绩页 (record)
- ✅ 历史答题记录列表，按时间倒序
- ✅ 显示每局的得分、用时、正确率
- ✅ 统计总答题数、总正确率、最高得分
- ✅ 退出登录按钮

## 🎨 六、UI 适配要点

### 6.1 全局样式对齐
- 主色调：`#8b1e2b`（酒红），和 Web 版完全一致
- 圆角、阴影、间距都和 Web 版保持 1:1 还原
- 字体大小用 `rpx` 自适应，不要用 `px`

### 6.2 交互适配
- Web 的 `:hover` 效果改成小程序的 `:active`（点击态）
- Web 的点击事件 `@click` → `bindtap`
- 阻止冒泡用 `catchtap`
- 输入框回车事件用 `bindconfirm`

### 6.3 组件替代
| Web 组件 | 小程序原生替代 |
|---------|--------------|
| Element Plus 弹窗 | 原生 `wx.showModal()` 或者自己写遮罩层 |
| Element Plus Toast | 原生 `wx.showToast()` |
| Element Plus 加载 | 原生 `wx.showLoading()` |

## ⚠️ 七、常见坑点和避坑指南

### 7.1 开发阶段坑
1. **没有 DOM**：所有操作 DOM 的代码全部重写，拼图不要用复杂拖拽，建议改成点击交换
2. **this 指向**：小程序 Page 里的方法 this 指向页面对象，注意不要和 app 搞混
3. **页面栈限制**：最多 10 层页面栈，答题页不要用 `navigateTo` 跳转自己，用 `redirectTo` 或者重新加载数据

### 7.2 审核阶段坑
1. **不要有诱导分享**：不要写「分享到群解锁更多题目」这种，会被拒
2. **不要有赌博性质**：不要做下注、抽奖类功能
3. **内容合规**：所有题目内容要过审，不要有敏感内容
4. **用户隐私**：不要强制索要头像昵称，只拿 openid 就可以正常使用所有功能

### 7.3 上线阶段坑
1. **域名白名单**：所有接口域名必须在微信公众平台配置，包括图片 CDN 域名
2. **HTTPS 要求**：所有请求必须是 HTTPS，不能用 HTTP，不能用 IP 地址
3. **包体积限制**：主包不能超过 2MB，图片全部放 CDN，不要打包进去
4. **版本兼容**：低版本微信可能不支持某些新 API，做好降级

## 📊 十、数据平滑迁移说明

现有 Web 版用户数据可以无缝迁移到小程序：
1. 后端通过 openid 关联同一个用户
2. 历史答题记录、等级、排行榜数据全部保留
3. 用户在小程序用微信登录后，自动关联到之前 Web 版的账号（如果手机号相同的话）
4. 不想做账号关联也没关系，相当于两套独立的用户体系，不影响使用
